# Decisions

Conservative choices made without stopping. Format: decision + reason.

- **Phase 1 — `#14D29E` (success) not added as a token.** No existing variable maps to it; adding one would introduce a new token. Success uses the existing green accent; Slashed/Failed use red. Reason: keep variable names, avoid new tokens.
- **Phase 1 — sidebar bg `#000C16` / active nav fill `#014237` applied at the shell/class level, not as global tokens.** The repo has no `--sidebar` token (sidebar uses `--bg-1`); changing `--bg-1` would darken every card. Reason: keep existing token names and avoid restyling unrelated surfaces.
- **Phase 4 — `design/reference.png` is not on disk.** Only the text spec exists. Used the text specs (Parts 1-5) as the source of truth. Reason: image unavailable; specs cover copy and layout.
- **Phase 4 — Transaction Detail has no "View on Explorer" button.** The subgraph row exposes the `callId` (bytes32), not the escrow transaction hash, so an explorer link would be invented. The SLA Canvas + Details card already trace the lifecycle. Reason: never invent data.
- **Phase 4 — SLA Canvas kept as the repo's isometric 4-plate board.** RULES says reuse existing viz (`NetworkGraph`, `SLACanvas`) and do not rewrite from scratch; the reference's 2D hex-node layout is a guide only. Reason: stack rule wins.
- **Phase 4 — panel radii fixed with heuristic scripts (`/tmp/radii2.mjs`, `/tmp/radii3.mjs`).** Only inline `borderRadius` values in a safe set were changed (fields -> 10, buttons -> 999, cards -> 14); tiny badges/dots untouched. Values outside the mapping were left as-is. Reason: avoid visual regressions on elements that would not benefit.
- **Phase 4 — generic `monospace` / `JetBrains Mono` replaced with `var(--font-mono)` (Geist Mono) in 7 panels, and `Nano`'s hard-coded code-block colors tokenized.** Reason: fonts are fixed to Geist + Geist Mono; no raw palette values.
- **Phase 6 — Landing replaced with the spec's section list; the older marketing sections (ribbon, live protocol panel, markets table, capabilities bento, compare, contracts) were removed.** SPEC_4 says "only these" sections in this order, so dropping the extras is instructed, not scope creep. Reused existing marketing copy for the Product/Developer cards where it already existed; no invented claims.
- **Phase 6 — Hero 3D scene deferred.** SPEC_4's Phase 6 is landing *layout without* the 3D scene; the `NetworkGraph` SVG holds the hero art slot and doubles as the Phase 7 fallback. Reason: keep phases atomic; `three`/`@react-three/*` are React-18-compatible pins added in Phase 7.
- **Phase 6 — navbar Product/Developers/Ecosystem became landing anchors (`/#product` etc.), not routes.** Spec defines them as in-page anchors; `/how-it-works` and `/providers` still exist and stay reachable via the footer. Plain `<a href>` so cross-page hash landing scrolls correctly.
- **Phase 7 — 3D hero gated by a low-end guard, not just WebGL presence.** SPEC_4 lists "low-end device" as a fallback trigger; used `hardwareConcurrency<=4 || deviceMemory<=4` plus reduced-motion and WebGL presence. Reason: WebGL can exist but be software-rendered (the TermFold WebView hung on the scene), so presence alone is not enough.
- **Phase 7 — 3D labels reuse the marketing chip CSS as `.viz3d-tag`.** drei `<Html>` needs static positioning, whereas `.viz-net__label` is absolutely positioned inside the SVG container; a separate class avoids fighting those rules.
- **Phase 8 — app panels verified by static review, not screenshots.** The panels render only from `AppShell`, which `AppGate` shows only when a wallet is connected; the harness browser has no injected wallet, so panels could not be rendered. Checked instead for fixed-width overflow, `outline:none` without a focus style, and raw dark palette literals. Landing + 5 marketing pages (public) were screenshot-verified.
- **Phase 8 — screenshot widths are 1280 (desktop) / 411 (phone), not the spec's 1440/375.** The harness browser exposes only `phone`, `desktop`, `fit` viewports. Both widths show no horizontal overflow, so the responsive intent holds.
- **Phase 8 — global `prefers-reduced-motion` broadened with spinner exceptions.** The old block disabled only three animations; many decorative infinite animations remained. A `*, *::before, *::after` rule now neutralizes them, with `.panel-loader-spinner`/`.pk-spin`/`.ui-btn__spinner` re-enabled so progress feedback survives.
- **Phase 8 — landing Transaction Flow gated via `useReducedMotion`.** framer-motion runs in JS, so CSS could not disable it. `initial`/`transition` fall back to the final state when reduced motion is on.
- **Phase 8 — user-motion preference (`store.reducedMotion`, `useApplyMotionPreference`) left as-is.** No Settings control sets that flag and no CSS keys on `[data-motion]`; the OS media query is the authoritative source, so wiring a new gating layer would be unused churn.
- **Batch B — "View on Explorer" / "Transaction Hash" kept omitted after a data audit.** Re-checked the subgraph schema: the `Call` entity (`subgraph/schema.graphql` lines 21-34) has no `txHash` field at all — it exposes only `callId` (bytes32). `txHash` exists solely on unrelated event entities (`ZkTierUpdate`, `UptimePing`, `StealthCall`, `DisputeRecord`), none keyed to the PayPerCall lifecycle. So no explorer link can be built without inventing data. Replaces the earlier Phase 4 note with the same outcome and stronger evidence.
- **Batch B — Transaction Detail gains a back arrow, "Transaction Details" eyebrow, status chip and a 4-step Stepper (Payment/SLA/Receipt/Settlement).** Step states derive from the existing `slaStages(status)` helper (no new data); `info` maps to `done`. Reason: SPEC_2 asks for the flow/stepper; reuse the same status mapping the SLA Canvas already trusts.
- **Batch B — SLA Canvas legend added (Success green / Pending blue / Failed red).** SPEC_2 wants the legend; swatches reuse `--accent`, `--border-hi`, `--danger`. Reason: no new tokens.
- **Batch B — data-flow untouched.** The stepper and legend are presentational; `History.tsx` still reads the same `useSubgraph` calls query. Reason: UI-layer-only rule.
